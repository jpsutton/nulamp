# Implementation decisions

This file records choices made where `spec/` is silent, where it offers options, or where the project deliberately departs from it. Add an entry whenever such a choice is made.

## Clean-room rule

The implementation is written only from `spec/`, public format standards and the documentation of third-party libraries. Contributors must not read Winamp source code from any place, and must not read the source of other re-implementations of classic skins.

## Project-level decisions

| # | Topic | Decision | Reason |
|---|---|---|---|
| D1 | Language | Rust, cargo workspace | Spec README §3 recommends a systems language with C interop |
| D2 | Text rendering | All text is 1-bit and hinted (FreeType mono mode) or uses skin bitmap fonts. No antialiasing, no subpixel rendering. Optional AA preferences from the spec default to off | Project owner requirement: small text must stay crisp and readable |
| D3 | Dialog toolkit | Own widget kit drawn with `genex.bmp` (05 §1.5). Native dialogs are used only for file pickers | Consistent skinned look; keeps D2 |
| D4 | Media library | In scope, although spec README §1 lists it as a non-goal. Local SQLite provider behind a provider trait; remote providers (Jellyfin, Subsonic) later | Project owner requirement. Designed from first principles, see `media-library.md` |
| D5 | Wayland | First run through XWayland; native compound-surface mode later (05 §6.5) | Wayland clients cannot position their own windows |
| D6 | Easter egg | The title-bar easter egg word is `NULAMP` | 02 §2.1 allows changing the word; avoids the original mark |
| D7 | Licence | MIT OR Apache-2.0. GPL or LGPL libraries only behind opt-in cargo features | Spec README §2.4 |
| D8 | `shufrep.bmp` layout (spec gap) | Repeat 28×15 at x 0, shuffle 47×15 at x 28; rows y 0 off, 15 off+pressed, 30 on, 45 on+pressed. Destinations: shuffle (164,89), repeat (210,89). EQ button 23×12 and PL button 23×12: off (0,61)/(23,61), off+pressed (46,61)/(69,61), on (0,73)/(23,73), on+pressed (46,73)/(69,73); destinations (219,58) and (242,58) | Spec 02 lists hit boxes but not sprites. Filled from the publicly known bitmap layout that real skins use (black-box interoperability fact, consistent with the 92×85 size in 01 §2.2). No source code consulted |
| D9 | Remaining time with 100+ minutes (02 §7.1) | The sign takes the x = 36 slot; the hundreds digit is not drawn | Spec gives one slot for "sign, or hundreds of minutes" |
| D10 | Large time digits, elapsed mode | With `numbers.bmp`, the minus line is cleared by copying (9,6) 5×1 to (40,32); with `nums_ex.bmp`, a blank cell is drawn at x = 36 when minutes < 100 | Spec defines the clear for the blank state only; same mechanism reused |
| D11 | kbps ≥ 10000, kHz ≥ 100 | kbps follows 02 §7.3 literally; kHz shows (value / 10) mod 10 and value mod 10 | Spec is literal for kbps; silent for kHz above 99 |
| D12 | Overlapping main-window sprites | Mono (212..239) and stereo (239..267) share column 239; shuffle (164..210) and repeat (210..237) share column 210. Mono and shuffle are drawn first | The right-hand sprite stays complete; matches the hit boxes (repeat starts at 210) |
| D13 | Presentation | `softbuffer` (CPU blit of each window's frame) instead of `wgpu`. Shapes use platform regions (XShape, `SetWindowRgn`). A GPU presenter can be added behind the same interface for platforms that need per-pixel alpha | Windows are small; CPU blits are pixel-exact and avoid a GPU dependency |
| D14 | Main-window title font | The skinned bitmap font (`text.bmp`) is the default (spec 02 §8.1 default is the system font). A title containing characters the bitmap font cannot draw falls back to the 1-bit system font automatically | Project owner preference: the bitmap font looks more authentic; the fallback keeps non-Latin titles readable |
| EQ1 | EQ marquee text (03 §1.3) | Band labels `70 Hz` … `1 kHz` … `16 kHz` (ISO `31.5 Hz`, `63 Hz`, …); text `EQ: 70 Hz: +12.0 dB` / `Preamp: -0.6 dB`; zero is `+0.0`. ISO centres are 31.5 and 63 Hz | Spec lists the label values and sign but not spacing, units or the sign of zero |
| EQ2 | EQ gain changes (03 §4.2) | The gain stage and every band gain glide to new values with a 10 ms one-pole curve. Each band runs its boost and cut band-pass as separate paths sharing input history, so a sign change cross-fades. A band whose gain reaches 0 stops; it restarts with cleared history and a gain rising from 0 | "No clicks" without a stated method; a click test bounds the sample-to-sample step |
| EQ3 | Limiter (03 §4.4) | One detector shared by all channels of a frame (linked), decayed once per frame. Order: detect = max(peak, detect), scale if above 0.930, then decay, so output never exceeds 0.930. Bypassed with the bands when the EQ is off or flat | Spec does not say per channel or linked; linking keeps the stereo image |
| EQ4 | EQ numerics (03 §4.2) | Coefficients designed in f64, stored and run in f32 (direct form I, b1 = 0). Filter states below 1e-15 are flushed to zero after each block instead of setting CPU flush-to-zero flags | Spec allows a DC offset or flushing; flushing needs no `unsafe` or platform code |
| EQ5 | Preset names (03 §6) | Read: UTF-8 if valid, else Windows-1252. Write: Windows-1252 when every character fits and the bytes would not read back as UTF-8, else UTF-8. NUL characters are dropped; names are cut at a character boundary to 256 bytes | Every name written reads back unchanged; ASCII and Latin-1 names stay compatible with the reference player |
| EQ6 | Auto-load key (03 §5.4) | The track's file name is the text after the last `/` or `\` | q2 files may come from Windows and paths may be URLs |
| EQ7 | ReplayGain details (07 §5) | Disabled → factor 1.0 (no no-tag gain). Gains parse as `[+-]digits[.digits]` plus optional `dB` (any case), no exponent; peaks missing, zero or invalid count as 1.0. `R128_*_GAIN` is used only when the `REPLAYGAIN_*_GAIN` of the same source is missing. No-tag gain and preamp are clamped to −14..+6 dB | Spec leaves these edge cases open |
| EQ8 | Constant-Q engine (03 §4.3) | Implemented as y = x + (G − 1) × band-pass(Q 1.41), which equals the bilinear transform of the given prototype. Both engines disable bands at ≥ 0.499 × sample rate (stricter than 2 × centre > rate) and design with the rate clamped to 4–384 kHz. Switching engines needs no restart | Algebraic identity; one code path for both engines |
| EQ9 | Gain stage (07 §4) | `Equalizer::set_pre_gain` (ReplayGain × its preamp) applies even when the EQ is off or flat; the EQ preamp applies only when the EQ is active | 07 §4 puts both in one stage but only the preamp depends on the EQ |
| EQ10 | Preset file writes (03 §6) | A new entry is appended after the last complete entry (a partial trailing entry is overwritten). EQF import matches `Entry1` ignoring case. Delete with no match leaves the file untouched; the temporary file is `<name>.tmp` next to it | Spec gives the rules but not these cases |
| EQ11 | EQ channels and settings | `Equalizer` takes 1..8 interleaved channels and panics otherwise; a trailing partial frame is left unchanged. `EqSettings` also carries the filter engine (03 §7) | 07 §4 requires up to 8 channels |
| TF1 | Apostrophe inside a word (title formatting, 10 §5.3) | A `'` between two alphanumeric characters is a literal apostrophe and does not start a quote. Elsewhere `'` quotes as specified | Spec 12 §2.3 requires `$caps(don't stop)` → `Don'T Stop`, which a strict quote rule would turn into an unmatched-quote error |
| TF2 | Syntax error extent (10 §5.3) | A malformed function argument or `[ ]` section is replaced by the error text when its closing `,`, `)` or `]` can still be found by balanced scanning; otherwise the error moves to the enclosing part, up to the whole string. An erroneous argument is passed to the function as the error text and is false; an erroneous section always shows the error text. A field name ends at the next `%` and cannot contain `( ) [ ] '` (nor `,` inside an argument). `$` not followed by a name and `(`, and a bare `(`, are syntax errors | Spec says "only that part is replaced" without defining the part |
| TF3 | Argument count (10 §5.3) | `$f()` has zero arguments, so `$tab()` gives no tab and the default of 1 is unreachable. Missing arguments are empty strings. Arguments after the 64th are ignored. Calls and sections nested more than 128 deep are syntax errors | Keeps the `$tab()` quirk; the limits prevent stack exhaustion |
| TF4 | Result size (10 §5.3) | Every string value (argument, function result, whole title) is cut at 65,536 bytes | `$repeat` and `$pad` with huge counts must not exhaust memory |
| TF5 | Truth of calls and variables (10 §5.3) | A call is true when any argument is true. Unknown functions still evaluate their arguments. Variable names are case-insensitive; `$get` is true when the stored value was true | Spec defines truth through arguments only; variables carry it so `$puts(a,%artist%)[$get(a)]` works |
| TF6 | Numbers (10 §5.3) | Reading saturates at the 32-bit range; `$add`, `$sub`, `$mul`, `$div`, `$mod` wrap. `$muldiv` rounds halves away from zero and gives −1 when the result does not fit. `$num` counts the sign in the width (`-05`). `$hex` of a negative number is its 32-bit two's complement. Arithmetic with no arguments, `$min()` and `$max()` give 0 | Spec gives 32-bit integers but not overflow or rounding details |
| TF7 | Text function edges (10 §5.3) | `$right` with negative n: whole string. `$substr`: a below 1 counts as 1, b past the end stops there, b < a gives nothing. `$strstr` with empty t: 0. `$split` with empty sep: separator absent. `$pad` with empty c: space; fill cycles from the first character of c. `$char` of an invalid code point: nothing. `$caps`: a word starts after any non-alphanumeric character. `$abbr`: words split on whitespace, each gives its first alphanumeric character; Roman numerals and `RPG` are matched case-sensitively. `$upper`/`$lower` use Unicode default case mapping (not locale-tailored) | Spec is silent on these cases |
| TF8 | Paths and fields (10 §5.3) | An extension starts at the last `.` of the last component, unless that dot is its first character. `$directory` with n < 1 or past the root gives nothing; path functions with n ≤ 0 keep everything (`trim`) or nothing (`part`). `%track%` and `%tracknumber%` stand in for each other, and `%folder%` comes from `%filename%`, when the caller does not supply them | Spec is silent on these cases |
| TF9 | Clock (10 §5.3) | `$systime_*` read local time through `chrono`; callers can pass a fixed time with `Formatter::format_at` | Testable; `chrono` reads the local zone safely in multi-threaded programs |
| PL1 | Playlist entry "metadata read" flag (10 §1, §3.2, §3.4) | `PlaylistEntry::title` doubles as the flag: writers emit `#EXTINF`, `Title<n>`/`Length<n>`, XSPF `title`/`duration` and B4S `Name`/`Length` only when `title` is `Some` | Keeps the crate's model small; the app maps "not yet read" to `None` |
| PL2 | Millisecond lengths (B4S `Length`, XSPF `duration`) | Rounded to the nearest second | Spec only says "correct seconds"; rounding matches what a time display shows |
| PL3 | `#EXTINF` parsing details (10 §3.1) | The title starts after the first comma outside a double-quoted attribute value (first comma if quotes are unbalanced); a fractional duration is truncated; no comma after the duration means no title. Attributes are kept even when the title is empty. Title truncation (260 chars) applies to M3U only | IPTV `tvg-name="a, b"` values contain commas; the spec's 12 §2.4 cases are unaffected |
| PL4 | `#UTF8` line (10 §3.1) | Switches the whole file to UTF-8, not only the following lines | It follows `#EXTM3U` in practice, which is ASCII |
| PL5 | Other `#EXT` directives (10 §3.1) | Unknown `#EXT…` lines and `#UTF8` never clear the pending title. `#EXTART`/`#EXTALB` set the artist/album of the next entry; `#EXTGRP` is ignored. The M3U writer does not write them | Spec's recommended new behaviour; optional metadata kept minimal |
| PL6 | HLS detection (07 §8.2) | Any M3U/M3U8 containing `#EXT-X-TARGETDURATION` or `#EXT-X-STREAM-INF` is reported as `Error::Stream` | Master playlists (`STREAM-INF`) are HLS too and must not be expanded as entries |
| PL7 | Location reading on Unix (10 §3.7) | Drive (`C:\…`) and UNC paths stay as given; drive-relative `\Music\a.mp3` is read as `/Music/a.mp3`; `file:///C:/x` gives `C:/x`; with a URL base, relative and root-relative paths are joined to the URL; `..` never climbs above a root. Case-insensitive fallback walks component by component and takes the first match in the directory listing, else keeps the path | Spec lists the inputs but not these combinations |
| PL8 | Location and value writing (10 §3.2, §3.7) | Relative only when the file is strictly under the folder (component compare, case-insensitive on Windows); otherwise unchanged. Line breaks in written values become spaces; `"` in `#EXTINF` attribute values becomes `'`. Legacy 8-bit M3U writes `?` for characters outside Windows-1252 | Keeps every written file line-safe and parseable |
| PL9 | PLS details (10 §3.3, §3.4) | Reader visits only the `File<n>` keys present with n ≤ `NumberOfEntries` (no 1..N loop, so huge counts are cheap); unreadable `Version` counts as 1. Writer also writes `Start<n>`/`End<n>` when set, after `Repeat<n>` | Round-trips everything the reader understands |
| PL10 | XSPF writing (10 §3.6) | `creator` is written only when the title starts with `<artist> - `, and that prefix is removed from `title`; files under the folder are written as relative URI references; `album` and `trackNum` are written when known | Reading `creator - title` back must give the same title |
| PL11 | ASX details (10 §3.5) | First `REF` of an `ENTRY` is used (others are fallbacks); title is `AUTHOR - TITLE` or `TITLE` alone; `REPEAT COUNT="n"` sets `repeat = n` extra plays (innermost wins; missing count = 0, never infinite). An XML declaration encoding is honoured too (`PARAM` wins). `.asx` content starting with `[Reference]` is read as ASX v2. No `ASX` element gives `NotAPlaylist`, so a `video/x-ms-asf` media stream falls back to playing as a stream | Literal reading of "sets repeats"; avoids endless loops |
| PL12 | Playlist detection (07 §8.2, 10 §2.4) | `application/x-mpegurl` is accepted as M3U in addition to the listed content types. Sniffing skips a UTF-8 BOM and leading whitespace and accepts UTF-16LE for every pattern. URL extensions ignore `?query` and `#fragment`; local paths do not | Common real-world variants |
| PL13 | Nested playlists (10 §2.3) | Max depth 8 counts the top-level playlist. A nested playlist already open up the chain, or beyond the depth, is dropped. One that cannot be fetched, has an unknown format, is invalid or is HLS is kept as an ordinary entry. Children take the parent entry's `repeat` when larger | Self-inclusion loads once; streams and missing files still fail at play time like any other entry |
| PL14 | Bookmarks file (10 §9) | Written as UTF-8 without BOM, LF endings, newline after the last title. Whitespace-only parts count as empty; a final location without a title line is dropped | Reader accepts LF, CRLF and CR, so either ending is safe |
| PL15 | XML playlist parsing | Own tolerant XML reader (no `quick-xml`) for B4S, XSPF, ASX and WPL. B4S `Playstring` is not percent-decoded. B4S/XSPF/WPL encoding: BOM, then XML declaration, then strict UTF-8, then Windows-1252 | ASX needs leniency (stray `&`, unquoted attributes) that a conforming parser rejects; one code path for all four |
| D15 | Playlist row font | Rows use the skin's `text.bmp` font by default, recoloured with the `pledit.txt` Normal/Current colours, 8-pixel rows at 1×; Ctrl+Numpad +/− scale the glyphs 1×–4×. Rows with characters the bitmap font cannot draw use the 1-bit system font. The spec's system-font list (04 §3.1) stays available as an option | Project owner preference for bitmap text |
| VIS1 | Visualizer sample conversion (06 §2.2) | Signed 8-bit = round(x × 32768) clamped to 16-bit, arithmetic shift right 8. Scope value = (sum of the channels' 8-bit values) / (8 × channels), rounded half away from zero, so the range is −16..16 | Spec says "keep the most significant byte" and "round" without the float conversion or rounding mode |
| VIS2 | Analyzer channels (06 §2.3) | Spectrum left = channel 0, right = channel 1 (mono uses channel 0 twice); further channels are ignored. The scope averages all channels | Spec defines only mono and stereo |
| VIS3 | Partial bins (06 §2.3 step 5) | The partial first bin is interpolated at the range start, the partial last bin at the range end; a range inside one bin uses its start. Catmull-Rom neighbours outside bins 0..255 are clamped. The W(x) formula is used as written, so bar 74 ends at bin 252.65 (the spec text says "near 253.6") | Spec gives "the fractional position" without saying which; the formula and the prose disagree by one bin |
| VIS4 | Spectrum time stamps (06 §2.1, §2.3) | Each spectrum is stamped with the output frame of its window's first sample (block stamps mark a block's first frame). `Analyzer` must be fed every block in order: a repeated stamp is ignored, a gap restarts the 512-sample window, an earlier stamp or a new sample rate also clears the history (1024 spectra, 512 scope blocks). Drawing picks the closest spectrum and the closest scope block independently; either missing within 400 ms means idle | Spec stamps blocks but not individual overlapping spectra |
| VIS5 | Double-size windowshade (06 §5.3) | 75 one-pixel columns using the main-window inputs and thick gap rule of §4.3 and all 75 scope values; scope colour is always 18 (as §5.2). The solid-scope "centre row 4" is counted from the top (level 5), where silence falls; the single-size shade centre is level 2 | §5.3 gives only heights; with level 4 a silent solid scope would be 2 pixels thick |
| VIS6 | Windowshade peaks (06 §5.2, §5.3) | Peaks are drawn only when ph / 256 > 0 (as §5.1) and their row is clamped to 0..4 (0..9), so a full-scale peak covers the top bar pixel | §5.2 states the 0..4 range, but 15 × 5 / 15 = 5 |
| VIS7 | Oscilloscope colour (06 §4.4) | A column's whole Lines run or Solid fill uses the colour c of that column's value | Spec computes one colour per column |
| VIS8 | Visualizer off and stop (06 §2.4) | With mode off, `Visualizer::tick` does nothing and `draw` paints nothing (the skin shows through). On stop the caller calls `reset` and `draw_background` once | Spec does not say what the off state shows |
| VIS9 | Idle animation (06 §2.5) | The idle frame replaces the input data and runs through the normal falloff and peaks. Scope values are round(7 sin((phase + x) × 0.1)) with phase +1 per tick; the bar position and phase advance only on ticks that use idle data | Spec does not say whether the idle frame bypasses the state machine |
| VIS10 | Plugin data (06 §7.1) | Waveform: per channel signed 8-bit (VIS1). Spectrum: the first 512 waveform values; the DC filter starts at x₋₁ = x₀, y₋₁ = 0 for each call; magnitude / 16 is truncated; bin 0's "previous bin" is itself; padding halves value 511 with integer division. One requested channel averages all source channels; two requested channels use channels 0 and 1 (mono duplicated). Float data: 576 PCM frames per channel and 256 magnitudes of a Hann-windowed FFT scaled by 2 / Σ window (a sine of amplitude A reads A) | Spec leaves filter start, rounding, edge bins and channel mapping open |
| MD1 | Tag library (10 §7.6) | `lofty` 0.24 parses every tag and serializes ID3v2, APEv2, Vorbis comments and MP4 `ilst`; nulamp keeps its own §7.2 key mapping and its own ID3v1 code. ASF/WMA files are not supported (`lofty` has no ASF reader), so the ASF column of §7.2 is not implemented | 0.24 is the newest `lofty` that builds with the workspace `rust-version` (1.88) |
| MD2 | Safe tag writing (09 §2, §3) | MPEG, AAC, Monkey's Audio, WavPack and Musepack: nulamp places the tags. A changed ID3v2 tag that fits in the old tag plus padding is written in place, padded to the old size; tags at the end are then rewritten in place (truncate and append when their size changes). Otherwise the file is copied to `.<name>.nulamp-<pid>-<n>.tmp` next to it with 1024 bytes of ID3v2 padding and renamed over the original. Other formats: `lofty` (which reads the whole file, truncates and rewrites it) works on a temporary copy that is then renamed over the original. MP4 `moov` is not moved before `mdat` (`lofty` updates it where it is). An emptied MP4 tag is removed by renaming `ilst` to `free` in place | Spec asks for in-place or atomic replacement; `lofty` alone does neither, and its MP4 tag removal leaves a `meta` atom it cannot read back |
| MD3 | ID3v2 frames written (10 §7.2, 09 §2) | Text frames are UTF-8 for 2.4 and UTF-16 with BOM for 2.3 (`lofty` converts). `year` is written as plain text to `TYER` (2.3) or `TDRC` (2.4). `mood` goes to `TMOO` in 2.4 and to `TXXX:MOOD` in 2.3 (2.3 has no `TMOO`; both are read). `WXXX` and `APIC` frames use Latin-1. Rewritten tags have no extended header, footer, CRC or unsynchronisation. ID3v2.2 frames without a 2.4 equivalent are dropped when the tag is rewritten | `lofty` drops `TMOO` from 2.3 tags, encodes the `WXXX` URL with the description's encoding and writes a one-byte terminator for an empty UTF-16 picture description |
| MD4 | Aliases and multiple values (10 §7.2) | Setting a field writes its first key and removes its aliases (for example `TXXX:ALBUMARTIST`, Vorbis `ALBUM ARTIST`/`ENSEMBLE`, MP4 `gnre`). Reading tries alias keys in table order; for each key the first entry wins. Vorbis `n/N` is written as `TRACKNUMBER=n`, `TRACKTOTAL=N`. NUL-separated values (ID3v2.4, APEv2) and several MP4 data items are joined with `; `. `TCON`: text after `(n)` references wins; several references or values are joined with `; `; numbers outside 0–254 stay as written | One source of truth per field after an edit; spec does not define multi-value display |
| MD5 | Rating scales (10 §7.2, §7.3) | APEv2 `Rating` holds 0–5 itself. Vorbis `RATING` and MP4 `rate` (written as text) are 0–100: read as the nearest multiple of 20, at most 5 stars. With an empty rating e-mail the first `POPM` frame is read and updated (keeping its e-mail and play counter); a new frame gets an empty e-mail; deleting removes every `POPM` frame (or every frame with the configured e-mail). A `rating` outside 0–5 is rejected | Spec gives no scale for APEv2 and no rule for several `POPM` frames |
| MD6 | ID3v1 text (10 §7.4, 09 §2) | Fields end at the first NUL; trailing spaces are then removed. Writing uses Latin-1 when every character fits and the bytes do not read back as different UTF-8 text, else UTF-8 cut at a character boundary (as EQ5). `track` takes the leading number of the field (`3/12` → 3). A tag left with no fields is removed. Enhanced `TAG+` tags are not read; the "system code page" read option is not offered | Garbage after a NUL is common; every value written reads back unchanged up to truncation |
| MD7 | Tags created on write (09 §2) | A newly created main tag (ID3v2 for MPEG, AAC, WAV and AIFF; APEv2 for Monkey's Audio, WavPack and Musepack) starts with the values merged from the file's other tags, as does a new ID3v1 tag (MPEG, AAC). Monkey's Audio, WavPack and Musepack update an existing ID3v1 tag but never create one. WAV `RIFF INFO` (`INAM`, `IART`, `IPRD`, `ICMT`, `IGNR`, `ICRD`, `ITRK`/`IPRT`, `ICOP`, `ISFT`) is read after the `ID3 ` chunk and updated when present. FLAC ID3v2 tags and AIFF text chunks are ignored; an APEv2 tag in an AAC file is kept unchanged | Creating an empty main tag would hide the old tags' values from other software |
| MD8 | APEv2 header flags (10 §7.5) | Bit 30 ("tag has no footer") is cleared in the header and footer `lofty` writes. Items marked read-only are rewritten like any other item. Front covers are written as `Cover Art (Front)` | `lofty` sets bit 30 although it always writes the footer |
| MD9 | Write API (08 §3.4) | A value for a field the format cannot store, or for a technical field, fails with `UnsupportedField` before the file is touched; deleting such a field is ignored. A write with no changes does nothing. A read-only file fails with `ReadOnly`. Cover writes replace the front covers (`APIC` type 3, FLAC/Vorbis picture type 3, every MP4 `covr`, APEv2 `Cover Art (Front)`) | Spec defines get/set per field but not these errors |
| MD10 | Reading details (10 §7, 08 §3.4) | Tags are parsed leniently: a malformed frame is skipped (for example a non-numeric `TYER`/`TDRC` year). `lofty`'s implicit conversions are off, so `gnre` is decoded with Appendix A and `TDAT`/`TIME` are left alone. Latin-1 ID3v2 text that is valid UTF-8 is read as UTF-8. `bitrate` is the average audio bit rate; `formatinformation` has `Format`, `Bit rate`, `Sample rate`, `Channels`, `Bits per sample`, `Length` and `File size` lines | Spec lists the technical fields but not their exact text |
| PF1 | Pixel UI font origin and licence | `nulamp-pixelfont` is an original proportional bitmap font drawn pixel by pixel for nulamp. No glyph was copied, traced or transcribed from another font or from memory of one. It is covered by the project licence (MIT OR Apache-2.0) | Clean-room rule; no third-party font licence to track |
| PF2 | Pixel font metrics | Both faces share one 13-pixel line box: ascent 11, descent 2. Cap height 8, x-height 6, ascenders 9, descenders 2 (g j p q y). Capital accents use the top two rows with a one-row gap above the cap height; lowercase accents sit one row above the x-height | Classic 8-point UI line height, with room for accents on capitals |
| PF3 | Pixel font spacing | Proportional, no kerning; each advance includes one blank column. Digits are tabular (advance 6 Regular, 7 Bold). Space advance is 3 (4 Bold) | Times and counters line up in menus and playlists |
| PF4 | Bold face | Bold is Regular widened by a one-pixel horizontal smear (stems become 2 pixels, each glyph one pixel wider). Hand-drawn overrides cover glyphs where the smear would close a counter (`"` `“` `”` `¨` `*` `×` `ø` `¢` `¶` `r` `ß`). Icons and complex symbols (`@` `©` `®` `™` `¼` `½` `¾` `★` `☆` U+FFFD) keep the Regular drawing | Keeps one design and identical metrics; ratings stars look the same in both faces |
| PF5 | Pixel glyph source format | `glyphs/regular.txt` and `glyphs/bold.txt`: `ascent`/`descent` header, then per glyph a `U+XXXX <advance>` line and 13 rows of `.`/`#`; `;` starts a comment. Parsed on first use from `include_str!`, no build script. Accented Latin-1 letters were composed from the base letter and a mark centred on the base's ink (accented i uses dotless ı, also included as U+0131), then stored as ordinary glyphs | Human-editable, reviewable in diffs |
| PF6 | Pixel font fallback | Coverage: U+0020–U+007E, U+00A0–U+00FF, U+0131 and a few UI symbols (dashes, quotes, bullet, ellipsis, €, ™, arrows, ✓, ▶, ★, ☆, U+FFFD). `has_char` lets callers fall back to the FreeType renderer per character (D2); `draw` draws U+FFFD for characters the font lacks. `fit` cuts with `…`. `draw_scaled` draws integer multiples (×2) by pixel replication | Same contract as the `text.bmp` fallback in D15 |
| D16 | Menu and dialog font | Menus and dialogs use nulamp's own pixel font (`nulamp-pixelfont`, 13-px line); strings with characters it lacks fall back to 1-bit FreeType | Project owner found 1-bit outline fonts at 11 px ugly |
