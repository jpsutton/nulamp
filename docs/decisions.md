# Implementation decisions

This file records choices made where `spec/` is silent, where it offers options, or where the project deliberately departs from it. Add an entry whenever such a choice is made.

## Clean-room rule

The implementation is written only from `spec/`, public format standards and the documentation of third-party libraries. Contributors must not read Winamp source code from any place, and must not read the source of other re-implementations of classic skins.

## Project-level decisions

| # | Topic | Decision | Reason |
|---|---|---|---|
| D1 | Language | Rust, cargo workspace | Spec README §3 recommends a systems language with C interop |
| D2 | Text rendering | All text is 1-bit and hinted (FreeType mono mode) or uses skin bitmap fonts. No antialiasing, no subpixel rendering. Optional AA preferences from the spec default to off | Project owner requirement: small text must stay crisp and readable |
| D3 | Dialog toolkit | Own widget kit drawn with `genex.bmp` (05 §1.5). Native dialogs are used only for file pickers | Consistent skinned look; keeps D2 |
| D4 | Media library | In scope, although spec README §1 lists it as a non-goal. Local SQLite provider behind a provider trait; remote providers (Jellyfin, Subsonic) later | Project owner requirement. Designed from first principles, see `media-library.md` |
| D5 | Wayland | First run through XWayland; native compound-surface mode later (05 §6.5) | Wayland clients cannot position their own windows |
| D6 | Easter egg | The title-bar easter egg word is `NULAMP` | 02 §2.1 allows changing the word; avoids the original mark |
| D7 | Licence | MIT OR Apache-2.0. GPL or LGPL libraries only behind opt-in cargo features | Spec README §2.4 |
| D8 | `shufrep.bmp` layout (spec gap) | Repeat 28×15 at x 0, shuffle 47×15 at x 28; rows y 0 off, 15 off+pressed, 30 on, 45 on+pressed. Destinations: shuffle (164,89), repeat (210,89). EQ button 23×12 and PL button 23×12: off (0,61)/(23,61), off+pressed (46,61)/(69,61), on (0,73)/(23,73), on+pressed (46,73)/(69,73); destinations (219,58) and (242,58) | Spec 02 lists hit boxes but not sprites. Filled from the publicly known bitmap layout that real skins use (black-box interoperability fact, consistent with the 92×85 size in 01 §2.2). No source code consulted |
| D9 | Remaining time with 100+ minutes (02 §7.1) | The sign takes the x = 36 slot; the hundreds digit is not drawn | Spec gives one slot for "sign, or hundreds of minutes" |
| D10 | Large time digits, elapsed mode | With `numbers.bmp`, the minus line is cleared by copying (9,6) 5×1 to (40,32); with `nums_ex.bmp`, a blank cell is drawn at x = 36 when minutes < 100 | Spec defines the clear for the blank state only; same mechanism reused |
| D11 | kbps ≥ 10000, kHz ≥ 100 | kbps follows 02 §7.3 literally; kHz shows (value / 10) mod 10 and value mod 10 | Spec is literal for kbps; silent for kHz above 99 |
| D12 | Overlapping main-window sprites | Mono (212..239) and stereo (239..267) share column 239; shuffle (164..210) and repeat (210..237) share column 210. Mono and shuffle are drawn first | The right-hand sprite stays complete; matches the hit boxes (repeat starts at 210) |
| D13 | Presentation | `softbuffer` (CPU blit of each window's frame) instead of `wgpu`. Shapes use platform regions (XShape, `SetWindowRgn`). A GPU presenter can be added behind the same interface for platforms that need per-pixel alpha | Windows are small; CPU blits are pixel-exact and avoid a GPU dependency |
| D14 | Main-window title font | The skinned bitmap font (`text.bmp`) is the default (spec 02 §8.1 default is the system font). A title containing characters the bitmap font cannot draw falls back to the 1-bit system font automatically | Project owner preference: the bitmap font looks more authentic; the fallback keeps non-Latin titles readable |
| PL1 | Playlist entry "metadata read" flag (10 §1, §3.2, §3.4) | `PlaylistEntry::title` doubles as the flag: writers emit `#EXTINF`, `Title<n>`/`Length<n>`, XSPF `title`/`duration` and B4S `Name`/`Length` only when `title` is `Some` | Keeps the crate's model small; the app maps "not yet read" to `None` |
| PL2 | Millisecond lengths (B4S `Length`, XSPF `duration`) | Rounded to the nearest second | Spec only says "correct seconds"; rounding matches what a time display shows |
| PL3 | `#EXTINF` parsing details (10 §3.1) | The title starts after the first comma outside a double-quoted attribute value (first comma if quotes are unbalanced); a fractional duration is truncated; no comma after the duration means no title. Attributes are kept even when the title is empty. Title truncation (260 chars) applies to M3U only | IPTV `tvg-name="a, b"` values contain commas; the spec's 12 §2.4 cases are unaffected |
| PL4 | `#UTF8` line (10 §3.1) | Switches the whole file to UTF-8, not only the following lines | It follows `#EXTM3U` in practice, which is ASCII |
| PL5 | Other `#EXT` directives (10 §3.1) | Unknown `#EXT…` lines and `#UTF8` never clear the pending title. `#EXTART`/`#EXTALB` set the artist/album of the next entry; `#EXTGRP` is ignored. The M3U writer does not write them | Spec's recommended new behaviour; optional metadata kept minimal |
| PL6 | HLS detection (07 §8.2) | Any M3U/M3U8 containing `#EXT-X-TARGETDURATION` or `#EXT-X-STREAM-INF` is reported as `Error::Stream` | Master playlists (`STREAM-INF`) are HLS too and must not be expanded as entries |
| PL7 | Location reading on Unix (10 §3.7) | Drive (`C:\…`) and UNC paths stay as given; drive-relative `\Music\a.mp3` is read as `/Music/a.mp3`; `file:///C:/x` gives `C:/x`; with a URL base, relative and root-relative paths are joined to the URL; `..` never climbs above a root. Case-insensitive fallback walks component by component and takes the first match in the directory listing, else keeps the path | Spec lists the inputs but not these combinations |
| PL8 | Location and value writing (10 §3.2, §3.7) | Relative only when the file is strictly under the folder (component compare, case-insensitive on Windows); otherwise unchanged. Line breaks in written values become spaces; `"` in `#EXTINF` attribute values becomes `'`. Legacy 8-bit M3U writes `?` for characters outside Windows-1252 | Keeps every written file line-safe and parseable |
| PL9 | PLS details (10 §3.3, §3.4) | Reader visits only the `File<n>` keys present with n ≤ `NumberOfEntries` (no 1..N loop, so huge counts are cheap); unreadable `Version` counts as 1. Writer also writes `Start<n>`/`End<n>` when set, after `Repeat<n>` | Round-trips everything the reader understands |
| PL10 | XSPF writing (10 §3.6) | `creator` is written only when the title starts with `<artist> - `, and that prefix is removed from `title`; files under the folder are written as relative URI references; `album` and `trackNum` are written when known | Reading `creator - title` back must give the same title |
| PL11 | ASX details (10 §3.5) | First `REF` of an `ENTRY` is used (others are fallbacks); title is `AUTHOR - TITLE` or `TITLE` alone; `REPEAT COUNT="n"` sets `repeat = n` extra plays (innermost wins; missing count = 0, never infinite). An XML declaration encoding is honoured too (`PARAM` wins). `.asx` content starting with `[Reference]` is read as ASX v2. No `ASX` element gives `NotAPlaylist`, so a `video/x-ms-asf` media stream falls back to playing as a stream | Literal reading of "sets repeats"; avoids endless loops |
| PL12 | Playlist detection (07 §8.2, 10 §2.4) | `application/x-mpegurl` is accepted as M3U in addition to the listed content types. Sniffing skips a UTF-8 BOM and leading whitespace and accepts UTF-16LE for every pattern. URL extensions ignore `?query` and `#fragment`; local paths do not | Common real-world variants |
| PL13 | Nested playlists (10 §2.3) | Max depth 8 counts the top-level playlist. A nested playlist already open up the chain, or beyond the depth, is dropped. One that cannot be fetched, has an unknown format, is invalid or is HLS is kept as an ordinary entry. Children take the parent entry's `repeat` when larger | Self-inclusion loads once; streams and missing files still fail at play time like any other entry |
| PL14 | Bookmarks file (10 §9) | Written as UTF-8 without BOM, LF endings, newline after the last title. Whitespace-only parts count as empty; a final location without a title line is dropped | Reader accepts LF, CRLF and CR, so either ending is safe |
| PL15 | XML playlist parsing | Own tolerant XML reader (no `quick-xml`) for B4S, XSPF, ASX and WPL. B4S `Playstring` is not percent-decoded. B4S/XSPF/WPL encoding: BOM, then XML declaration, then strict UTF-8, then Windows-1252 | ASX needs leniency (stray `&`, unquoted attributes) that a conforming parser rejects; one code path for all four |
